# S2J Site Policy Manager - 製品の方向性

本ファイルは、S2J Site Policy Manager の製品方針を検討したメモです。仕様本文ではありません。方向性を確定したあと、`specs.md` と `docs/` に反映します。状態は検討メモです。記録日は2026-09-29です。

## 背景

KIS WordPress のエコシステム仕様では、本プラグインを別リポジトリの汎用プロダクトとして置いています。担当する公開ページは、下記の2つです。

* 個人情報の保護方針 (`/privacy/`)
* 情報セキュリティ基本方針 (`/informationsecurity/`)

## 経緯

当初の仕様メモでは、データモデルを「法務向けのカスタム投稿タイプ」としていました。プロジェクト名も S2J Legal (`s2j-legal`) でした。

検討は、右記の問いから始まりました。「WordPress では、プライバシー・ポリシーのひな型を、管理画面から作れます。作ったページは、専用ページとして指定できます。企業サイトでは、情報セキュリティ・ポリシーにも、同種のジェネレータの需要があると思います。法務に関するページとして、ほかに需要があるものは、何かあるだろうか」。

会話では、範囲が下記のように広がりました。

1. 情報セキュリティ基本方針のひな型は、企業サイトで需要がある。
2. 公開するのは方針であり、詳細な社内規程とは分ける。
3. プライバシー、Cookie、利用規約、免責など、企業サイトで繰り返し見るページを種別として整理できる。
4. 単体のひな型追加よりも、WordPress のプライバシー機能をほかの種別に広げる形が自然である。
5. ひな型には専門家の監修が必要である。法的適合の保証とは別の製品である。
6. 質問への回答で節を組み立て、サイトの構成を確認し、ひな型の版と見直し日を管理する形まで含む。

既存の第三者プラグインには、プライバシーポリシーや利用規約の生成を主機能にするものがあります ([WP Legal Pages](https://wordpress.org/plugins/wplegalpages/))。日本の企業サイト向けに、ページの紐づけと見直しの管理を持つことで、差別化の余地が生まれます。

## 結論

表示名は S2J Site Policy Manager とします。日本語の画面表示は「サイトポリシー」とします。プラグインのスラッグは `s2j-site-policy` とします。

「Legal」という名称は、ひな型を使えば法的要件を満たす、という印象を与えます。本プラグインが約束するのは、ポリシーの種別、公開ページ、ひな型の版、確認日の管理です。法的適合の保証は約束に含めません。

名称は、S2J Alliance Manager と同じく、S2J の Manager という製品名の並びです。

リポジトリ名は `s2j-site-policy-manager` とします。プラグインのスラッグ `s2j-site-policy` だけでは、何をするものかが伝わりません。

`package.json` の description は `The WordPress privacy page, extended into a ledger of site policies.` とします。

KIS は、この台帳のユーザーです。KIS が公開するのは、背景に書いた2種別で足ります。プラグインは、使わない種別を未設定のまま持てます。

製品の本体は台帳です。診断用のダッシュボードや、外部サービスの検出は、台帳のあとに載せる機能です。

## 採用する考え方

WordPress 本体は、プライバシー・ポリシーについて、下記をすでに持っています。

* 設定画面からひな型を生成し、専用ページを指定できる
* オプション `wp_page_for_privacy_policy` で、そのページを指す
* `wp_add_privacy_policy_content()` により、テーマやプラグインが、ガイドに項目を追加できる
* ブロックテーマでは `templates/privacy-policy.html` を使える
* クラシックテーマでは `privacy-policy.php` を使える

プライバシー種別では、Core の `wp_page_for_privacy_policy` を読み書きします。プラグイン独自のページ指定は持ちません。ほかの種別は、同じ形で種別と固定ページを束ねます。

公開してよいのは方針です。下記のような社内規程は、対象外です。

* パスワード・ポリシー
* アクセス制御の規程
* インシデント対応の手順
* バックアップの規程

ひな型は、節ごとのたたき台にします。WordPress のプライバシー・ポリシー・ガイドと同じ方式です。質問の回答から全文を書く方式は、初版の範囲外です。

ひな型の位置付けは、下記のとおりです。

* 専門家の監修を受ける前提の、作成支援である
* 監修前の文章には「検討用」と表示する
* 監修済みの版だけが、版番号と監修者を持つ
* 法的適合の確認は、ユーザーまたは専門家の責任である
* 本文は、このリポジトリに同梱する。別配布にはしない
* 監修済み文章のライセンスは、プラグインと同じ GPL-3.0-or-later である

テンプレートに持たせるメタデータは、下記のとおりです。

* 版。例は1.4.0である
* 対象とする法域
* 監修日
* 監修の有無
* 監修者

法改正やガイドラインの更新があった場合、利用中の版に見直しを推奨します。「一度生成したら、終わり」ではありません。

## データモデル

これらのページは、投稿の集合ではありません。各種別は1ページです。本文は通常の固定ページとし、ブロックエディターで編集します。プラグインが保持するのは台帳です。

台帳の1行が持つ項目は、下記のとおりです。

* ポリシー種別
* 固定ページの ID
* 状態
* ひな型の版
* 最終確認日
* 次回確認日

最終確認日は、投稿の更新日とは別です。本文を編集した日と、方針として見直した日は、別の日付です。更新日の算出は S2J Content Dates Service の役割です。本プラグインの確認日は、方針を見直した日付です。

```text
policy_type
  privacy                core privacy page (wp_page_for_privacy_policy)
  information_security   page
  cookie, terms, disclaimer   optional
fields: page_id, status, template_version, last_reviewed, next_review
```

## 種別の範囲

器は、種別をあとから増やせる形にします。初版で文章まで持つのは、KIS が現に使う2種別です。

1. 個人情報の保護方針
2. 情報セキュリティ基本方針

製品としての次の候補は、下記の3種別です。文章は、器ができてから足します。

* Cookie ポリシー
* サイト利用規約
* 免責事項

同じ器にあとから載せる候補は、下記のとおりです。

* 特定商取引に関する法律にもとづく表記
* 著作権と知的財産権
* Web アクセシビリティ方針
* AI 利用方針
* ソーシャルメディア・ポリシー
* サプライヤーの行動規範
* 採用応募者が提出する個人情報の取扱い
* 問い合わせで扱う個人情報の取扱い

分類の目安は、下記の3つです。

### 法令と権利

* プライバシー・ポリシー
* Cookie ポリシー
* サイト利用規約
* 特定商取引に関する法律にもとづく表記
* 免責事項
* 著作権と知的財産権

### コンプライアンスとガバナンス

* 情報セキュリティ基本方針
* Web アクセシビリティ方針
* AI 利用方針
* ソーシャルメディア・ポリシー
* サプライヤーの行動規範

### 個別用途

* 採用応募者が提出する個人情報の取扱い
* 問い合わせで扱う個人情報の取扱い

## 段階

### 初版

KIS 向けに、下記を実装します。

* 種別の登録
* ページとの紐づけ
* 節ごとのたたき台
* 最終確認日と次回確認日

### 次の段階

* Cookie ポリシー、利用規約、免責事項を種別に足す
* ひな型の版メタデータを持たせる
* 管理画面で公開状況を一覧する

### その後

* フォーム、コメント、埋め込みなど、サイト機能の検出ヒントを出す
* 監修済みのひな型を、このプラグインに含める
* Web アクセシビリティ、AI 利用、特定商取引に関する法律などを種別に足す

検出は断定しません。表示文は「関連するコードが見つかったので、利用の有無を確認してください」までとします。カバレッジの割合表示と、外部タグの自動検出は、台帳が安定したあとの機能です。

## 非目標

* 法的適合を保証する表現
* 社内規程の公開
* 法務向けのカスタム投稿タイプ
* 初版での文章の自動生成
* 初版での外部サービスの検出
* WordPress 本体にあるプライバシー機能の置き換え

## 決定

* 監修済み文章のライセンスは、プラグインと同じ GPL-3.0-or-later とする。
* ひな型の本文は、このリポジトリに同梱する。別配布にはしない。

## 未決事項

* 監修者の確保
